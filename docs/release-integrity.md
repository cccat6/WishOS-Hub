# 可验证发布

发布流程分开构建与上传。构建工作流只有读取仓库的权限，生成带来源的各平台归档；
发布工作流需要维护者显式选择成功的 build、提交、tag 和完整产物集合。

归档首先与该 build 的逐文件清单核对，再从同一组已验证字节生成 SHA256SUMS 和
publication.json。发布过程中保留 draft，上传后比较远端大小与摘要，成功后由维护者
复核并确定可见性。并发发布按 tag 串行化，已存在的资产替换需要明确授权。

来源提交、workflow run、artifact ID、归档 SHA256 共同标识一个构建批次。更换归档后
重写摘要不能替代来源核验，旧批次的验收也不能证明新源码。相关回归覆盖混合批次、
缺失平台、重复资产、旧清单和远端字节变化。

公开前检查源码历史、Release 描述／附件、Actions 产物／日志及部署元数据。运行配置、
录音、私有会话、设备标识和本机交接记录不进入产品清单。依赖许可和声明的测试范围
随发布保留。
