# WishOS 应用制作与修改检查单

这是上游应用作者的指导，不是固件新策略或交付许可。每次制作、修改应用都逐项核对；
内部保留实现位置与验证证据，不适用项注明原因。交付时只报告已证实的行为和待验事项，
无需把整张清单打印给用户。没有目标访问时，区分静态检查、模拟场景与待做的真机验收。
检查依据是当前 boot 的公开能力和契约；固定版本参考不能覆盖设备实际 schema。

## 交付前逐项核对

- [ ] **目标与运行环境**：发现 boot、组件、显示配置、几何、字体、运行时版本、存储和预算。
  同一 MCU 不代表同一外设；只用系统公开资源，不直接操作 GPIO/RTOS/寄存器。
  新建应用和修改完整 revision 都执行本清单，不因上一版通过而跳过受影响的路径。
- [ ] **动态值**：为时钟、倒计时、电量、联网状态、远端数据等写清来源、事件或定时更新、
  显示精度和失效反馈。静态页面模板不等于会更新的程序；只在初次打开读取一次不够。
  网络超时、断线、时间无效时按应用需要保留旧值并标明过期/更新时间或显示替代内容，
  不把错误当作新值。对重复通知、跳过的 tick、对时和时区变化做场景检查。
- [ ] **时间与显示节奏**：墙钟来自系统当前时间及配置的时区，不靠回调次数累加。
  倒计时/经过时间用单调时间和截止点，不受 NTP/时区更改影响；重开/重启的恢复语义
  由应用明确选择。定时器用于唤醒重算，不是时间真值。依据实际驱动声明的延迟、
  局部更新、队列和完成模型选择显示频率，不能只按 LCD/OLED/EPD 名称判断。
  可实时更新的显示要持续更新其动态部分，但同一分钟的分钟制时钟不重复提交。
  慢刷配置可选随内容刷新、分钟/小时/天精度、标注更新时间或不显示时钟；这是应用策略，
  不是系统替所有应用做的决定。时间或时区变化后重算显示，即使上次已画过同一字段。
- [ ] **呈现与并发**：维护完整模型，按实际 `values` 契约整体替换，不能把局部字段当增量合并。
  更新指定 view 与导航/激活不同。保留 view/revision/job 身份；仅把实际完成的几何用于
  `hit_test`，处理尚未完成或已被替换的画面。根据实际队列/背压/拒绝策略合并、等待或
  反馈更新；等待显示不能阻塞事件循环、录音或输入。不得暂停/打断已提交的 BUSY/DMA
  硬件工作；取消只在声明的安全边界生效。完成模型以驱动为准，传输完成不等于光学完成。
- [ ] **字体、图像和布局**：使用目标真实字号范围、完整系统字库或合规扩展字体，
  不按当前页面几个字临时裁系统字库。确认动态文字、帮助、错误态、目标方向/尺寸
  不溢出或缺字。图片格式、尺寸、色彩空间、解码峰值与来源访问方式匹配声明能力；
  流式传输不能使非流式解码器自动支持大图。
- [ ] **输入与可达性**：短按、长按、多击、组合键、触摸/旋转等只使用已声明能力。
  定义时长、去抖、优先级/消费方式，避免同一动作在脚本和规则重复执行。
  操作帮助、首次提示和实际绑定一致；系统 Home/voice/恢复入口始终可达。
  测试按住再松开、快速重复、显示未完成时输入和离开应用，不能让新应用吃到旧动作。
- [ ] **执行位置与资源**：确定性计时、事件和简单联网本地离线运行；只有显式应用动作
  才请求上游。AI 通过系统 API，不能由设备重做 Harness 协议。大代码、多文件、图片、
  书籍/索引和重 JSON/XML 由上游处理，控制信封与资源分离并按声明预算分页/分块。
  使用设备下载/安装提供者及配额，不隐式回退内部 Flash。录音用独立可解码压缩块；
  无可移动录音存储时只有短 RAM 缓冲和可报告丢失，录音保留是显式用户策略。
- [ ] **生命周期与失败**：模块顶层只定义纯代码/数据；系统调用放在 `on_start` 或事件/
  完成回调中。注册前后、拒绝、异步失败、退出/替换、存储移除/满、OOM 都按资源契约
  收尾。释放自己的计时器、监听、句柄/流/操作等；驱动独立工作不因 VM 退出就被强停。
  回调不再更新失效的 view；请求保留 origin VM、boot、revision 和 request_id。
  掉线/响应丢失先查回执，不能重放结果不明的变更，也不能把旧回复发给新实例。
- [ ] **包与结果动作**：整文件构造新的完整不可变 revision，复用文件核验摘要，先预检，
  再等原生 validate 票据，带对应 revision 安装，显式激活。托管结果只有有序
  application/system 动作；不先用 MCP 执行再返回重复动作。保留 `$previous` 的邻接含义；
  替换前的处理屏障用 processed，queued 只代表送达。遵守文件/票据/传输租约交接，
  不加绕过系统生命周期的重复清理。详读 `wishos-packages` 与 `managed-services`。
- [ ] **验收证据**：分别确认源/包预检、安装提交、运行时启动、对应 view/revision 的
  显示完成和实际行为。静态编译不执行 `on_start`，不证明任意程序语义、峰值内存或
  以后启动一定成功。验证本次受影响的跨层场景：重复更新、断网、对时/时区变动、
  异步拒绝、切换/退出、资源不足；未测的目标硬件不能由模拟/编译结果代替。

## 少量通用正确写法

下面是算法示意，`clock`、`toLocalMinute`、`submit` 是应用对已发现系统 API 的封装，
不是新增的 WishOS API。系统调用只能在生命周期/事件回调里发生，具体字段和事件从
`get_guidance` 的 `runtime-apps`、`callbacks`、`dynamic-ui`、`display-interface`、
`managed-services` 以及当前设备 schema 获取。

### 时间重算与完整模型

```lua
-- 在 on_start 注册的定时/时间设置通知回调中执行。
local function tick()
  local now = clock()  -- 每次读系统墙钟、单调时间、有效标记与应用使用的时区。
  model.time = now.valid and toLocalMinute(now) or "时间未同步"
  if deadline then model.remaining = math.max(0, deadline - now.monotonic) end
  local key = encodeVisibleModel(model)  -- 包含所有可见字段，不只分钟数。
  if key ~= lastCompleted and not pending then
    pending = key
    local accepted = submit(model, function(ok) -- 提交完整快照，回调关联此 view/revision。
      if ok then lastCompleted = key end
      pending = nil -- 失败后，下次 tick 仍可重试同一模型。
    end)
    if not accepted then pending = nil end
  end
end
-- 暂停时保存 deadline-now.monotonic，恢复时以 now.monotonic+remaining 重建 deadline。
-- 即使回调延迟/少跑几次也不累积漂移；时区/NTP改变只重算墙钟，不改变倒计时。
```

应用可在显示忙时只保留最新完整模型，并在已提交工作的终态后继续；这是可选的应用
合并策略，不得假设所有队列都用 latest，也不能把请求准入成功记为显示成功。
若采用模型去重，失败/拒绝后须允许重试同一模型，不能被已提交但未完成的 key 永久挡住。

### 等待对应请求完成

```lua
local view
function on_start()
  local r = notes.request('/sys/ui', 'open', {
    path = notes.resolve('ui.json')
  }, function(event)
    if event.event == 'completed' then
      -- 只按该请求回执解释 completion.kind；此处才使用已完成几何或确认显示阶段。
      view = event.data.view_id
    else
      -- 依据拒绝/取消/失败语义处理，不无限重开，也不强停底层显示。
      view = nil
    end
  end)
  if not r.ok then view = nil end  -- 同步拒绝不会留下完成监听。
end
```

未选择交互式显示的应用不必安装触摸或周期时钟；清单约束的是所承诺行为的正确实现。
新增常见错误应归入相应通用机制和实例，不能为某个 demo 增加内核分支或全局默认策略。
